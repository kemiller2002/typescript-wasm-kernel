data-each — keyed list, add / remove / reorder

Clicking a row dispatches selectItem via the default click trigger on a plain <li> (no tag-specific mapping needed); the nested Remove button dispatches its own event. Both carry the row's key. Reordering moves the existing DOM nodes — open devtools and watch the elements, not just the text, move.

Effect execution & every EffectOutcome

Each button issues a real Http effect through the kernel; this page installs a fake fetch so no server is required — the kernel's own fetch/timeout/abort/classify logic is unmodified.

Error boundary

Both failures are caught at the kernel's single chokepoint and reported to diagnostics below — neither crashes the page or leaves other bindings unable to update on the next good round-trip.
